HOW TO WORK WITH FreeCAD AND Blender MCP SERVERS
================================================================

The project has two CAD MCP servers configured in .mcp.json:
  - freecad: uvx freecad-mcp
  - blender: uvx --python 3.12 blender-mcp

Both work the same way under the hood: a small server inside the app
(FreeCAD or Blender) listens on a localhost port, and the MCP wrapper
forwards `execute_code` calls into the app's Python interpreter.

----------------------------------------------------------------
1) FreeCAD MCP
----------------------------------------------------------------

PORT: 9875 (XML-RPC)

STARTUP CHECKLIST (do this before asking Claude to run anything):
  a. Open FreeCAD (the GUI app, not headless).
  b. View -> Workbench -> "MCP Addon" (or whatever the addon menu is
     called after install). This starts the XML-RPC server on 9875.
     Status bar / Report View should print something like
        "FreeCAD MCP server listening on 127.0.0.1:9875"
  c. Leave FreeCAD open with at least one document tab visible (an
     empty New file is fine; the macro itself creates its own doc).

VERIFY IT'S UP (from any terminal):
     py -c "import xmlrpc.client; s=xmlrpc.client.ServerProxy('http://127.0.0.1:9875',allow_none=True); print(s.execute_code('print(1+1)'))"
  Expected: {'success': True, 'message': 'Python code execution scheduled. \nOutput: 2\n'}

DIRECT-SOCKET BYPASS (what Claude actually uses):
  Instead of going through the MCP wrapper, Claude calls XML-RPC
  directly with the `execute_code(<python source>)` method. This is
  much more reliable for long-running boolean operations because the
  MCP wrapper sometimes times out before FreeCAD finishes.

RUNNING A MACRO FROM A TERMINAL:
  See template at:
     C:\3D-Project\01_MECHANICAL\02_CASSETTE_HEAD\cylinder\_run_in_freecad.py
  Pattern:
     code = '''
     import FreeCAD
     for n in list(FreeCAD.listDocuments().keys()):
         try: FreeCAD.closeDocument(n)
         except: pass
     exec(compile(open(r"<macro_path>", encoding="utf-8").read(),
                  r"<macro_path>", "exec"),
          {"__name__": "__main__"})
     '''
     xmlrpc.client.ServerProxy("http://127.0.0.1:9875",
                               allow_none=True).execute_code(code)

GOTCHAS:
  - `execute_code` returns IMMEDIATELY ("scheduled"). It does NOT wait
    for FreeCAD to finish. For long jobs (cylinder = ~30-60s) the
    response message will be EMPTY -- that does not mean failure.
    Confirm completion by polling the output STL's mtime instead.
  - For long jobs, the wrapper may raise `_queue.Empty` as a Fault.
    That's also not a failure -- the code still runs to completion
    inside FreeCAD. Verify via output files.
  - FreeCAD must have GUI up for `FreeCADGui` calls (view rotation,
    PNG render). The macro guards these with `if FreeCAD.GuiUp`.
  - `import FreeCAD` works inside `execute_code`, but the script's
    `__name__` defaults to FreeCAD's console module unless you pass
    `{"__name__": "__main__"}` to exec().

CLOSING DOWN:
  The MCP server stops when FreeCAD closes. No cleanup needed.

----------------------------------------------------------------
2) Blender MCP
----------------------------------------------------------------

PORT: 9876 (raw TCP socket, JSON line protocol -- NOT XML-RPC)

STARTUP CHECKLIST:
  a. Open Blender 3.x or 4.x (the GUI, not headless).
  b. Edit -> Preferences -> Add-ons -> search "BlenderMCP" -> enable.
     (Install from .zip if not already installed -- the blender-mcp
     repo has the addon.)
  c. In the 3D viewport, press N to open the side panel.
  d. Open the "BlenderMCP" tab on the right edge.
  e. Click "Start MCP Server". The panel should say
        "Connected on 127.0.0.1:9876"
  f. Leave Blender open with the default scene (or any scene) loaded.

VERIFY IT'S UP:
     py -c "import socket,json; s=socket.create_connection(('127.0.0.1',9876),timeout=2); s.sendall((json.dumps({'type':'execute_code','params':{'code':'print(1+1)'}})+chr(10)).encode()); print(s.recv(4096).decode())"

PROTOCOL DIFFERENCE FROM FREECAD:
  Blender MCP speaks raw TCP with newline-delimited JSON, not XML-RPC.
  Each message is one JSON object terminated with \n:
        {"type": "execute_code", "params": {"code": "<python>"}}\n
  Response is also one JSON line:
        {"status": "success", "result": "<stdout>"}\n

RUNNING A SCRIPT FROM A TERMINAL:
     import socket, json
     s = socket.create_connection(("127.0.0.1", 9876), timeout=30)
     msg = json.dumps({"type":"execute_code",
                       "params":{"code": open(<path>).read()}}) + "\n"
     s.sendall(msg.encode())
     resp = b""
     while not resp.endswith(b"\n"):
         resp += s.recv(65536)
     print(json.loads(resp.decode()))

TYPICAL USE CASES (CSM V3 context):
  - Import a freshly-built STL from FreeCAD:
        bpy.ops.import_mesh.stl(filepath=r"<path>.stl")
  - Apply machine-coordinate transforms (Z up matches CSM convention).
  - Render assembly previews with PBR materials (PETG translucency).
  - Composite multiple components into one scene for visual ICD
    verification (cassette base + cylinder + cam + sinker + retainer).

GOTCHAS:
  - Blender's bpy operators sometimes need a valid context. Wrap
    risky ops in:
        with bpy.context.temp_override(area=..., region=...):
            bpy.ops.xxx()
    or use the lower-level bpy.data API instead.
  - bpy.ops.import_mesh.stl was REMOVED in Blender 4.0+. Use
    bpy.ops.wm.stl_import(filepath=...) instead (or check the
    Blender version first and branch).
  - Long renders block the socket. If a job will take more than ~10s,
    spawn it asynchronously inside Blender and poll for the output
    file (same pattern as the FreeCAD STL mtime poll).

3) Shared workflow tips
----------------------------------------------------------------

CLAUDE-DRIVEN WORKFLOW WE'RE USING:
  1. Edit the macro source in the repo (e.g. CSM_V3_Cylinder_V3_0.FCMacro).
  2. Ask Claude to run it -- Claude calls execute_code() and polls the
     output STL mtime to know when it's finished.
  3. Claude reports file sizes / volumes back to you.
  4. You open the STL in your slicer (or import it in Blender via the
     Blender MCP for visual check) and print.
  5. After physical test, you tell Claude which slot won; Claude
     updates the macro's locked values and the ICD if interfaces
     changed; commit.

WHY DIRECT XML-RPC / TCP INSTEAD OF THE WRAPPED MCP TOOLS:
  - More reliable for long-running CAD jobs.
  - Easier to debug (one print statement away).
  - Works even when the MCP harness restarts -- the in-app server
    keeps running.
  - You can also use the wrapped MCP tools from Claude's tool menu;
    they go to the same port. Direct calls just bypass a layer.

WHEN MCP TOOLS STOP RESPONDING:
  - First: is the app (FreeCAD / Blender) still open?
  - Second: did the in-app server addon get unloaded? (Toggle off/on.)
  - Third: try a `py -c` probe from terminal to confirm the port.
  - Fourth: restart the app, then re-enable the addon.
