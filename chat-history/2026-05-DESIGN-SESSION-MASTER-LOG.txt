================================================================

The project entered May 2026 with:
- Locked Cylinder V3.0 (slot 1.22 wide x 3.0 deep, spring groove 1.3)
- Locked Cam Ring V6.5
- Locked Sinker Ring V1.2.1

  Blender hero render exposed as visually wrong.

Architecture documents that existed:
- MACHINE_DATUMS.md R1 (basic constants)
- INTERFACE_CONTROL.md R1->R2 (9 interfaces locked)

What was missing:
- World coordinate system (only cylinder-local Z was defined)
- Three-layer architecture vocabulary

  (docs assumed NEMA 17 + NEMA 11 -- BOM had NEMA 23 + MG90S)
- Frame architecture had floating ambiguity

================================================================

Trigger: a comment that the early Blender hero render didn't match
the ChatGPT-generated machine poster. Investigation revealed that
the docs and the poster were both partially right and partially
wrong, and neither matched the actual BOM purchases.

Resolution: rewrite the architecture from the ground up.

Documents created or revised:

  (a) MACHINE_COORDINATE_SYSTEM.md  R1  (NEW)
      World frame (Z up, X motor side, Y operator).
      Cylinder-local frame (Z=0 at cylinder bottom).
      Locked transform: CYL_BOTTOM_WORLD_Z = 181 mm.
      Right-handed.

  (b) MACHINE_DATUMS.md             R1 -> R5
      R1 (2026-05-17): initial datums
      R2 (2026-05-20): added world-Z mapping, frame geometry, bought-parts
      R3 (2026-05-22): BOM ALIGNMENT -- discovered V11 had NEMA 23+gearbox
                       (not NEMA 17), MG90S servos (not NEMA 11 steppers),
                       S-250 PSU (not LRS-50), 60T+20T pulleys (not 60T+16T)
      R4 (2026-05-24): BELT GEOMETRY FIX -- motor moved from (90,-100) to
                       (85,-47) so center distance = 97.29 mm matches the
                       actual 405 mm belt geometry.  Separated 3 ratios:

  (c) INTERFACE_CONTROL.md          R1 -> R6

          - NEW Sec 0: Three-Layer Architecture
                Layer 1 = Precision Knitting Core (cassette)
                Layer 2 = Structural Frame (wood + aluminum)
                Layer 3 = Automation (motors, electronics, mast)
          - NEW Sec 1: Datum Chain (master = aluminum plate top face)
          - NEW Sec 2: 5 Service Envelopes summary
          - Frame architecture totally re-spec'd
          - NEW Interface 10 (Touchscreen Mast - dual 2020, isolated)
          - NEW Interface 11 (Sock Take-Down Column - D100 reserved)
          - NEW Sec 4: Phase 1 / 1.5 / 2 / 3 upgrade path
      R4 (2026-05-22): BOM ALIGNMENT corrections to Interfaces 5 + 6
          - Interface 5: MG90S servos (NOT NEMA 11 steppers)
          - Interface 6: NEMA 23 + gearbox, 60T+20T+405mm belt
          - Motor Mount V1.3 flagged OBSOLETE -> V1.4 needed
      R5 (2026-05-22): Interface 12 (Shaft / Bearing Stack) added
          - Floating-top / fixed-bottom architecture formalized
          - Pulley sits BELOW lower bearing (not between)
          - DO / DON'T design rules
          - New invariant A8 (bearing stack)

            NOT precision synchronized actuation

            (Justified by Phase 1.5 B1 slack sensitivity = ±2 mm.)

            dual-roller servo-controlled nip system
          - Phase 1 hanging weight reclassified as bring-up tool
          - Reason vacuum / conveyor / spring NOT chosen documented

  (d) SERVICE_ENVELOPES.md          R1  (NEW, 2026-05-20)
      SE1 = Cylinder removal (vertical lift)
      SE2 = Cam ring extraction (annular access from below)
      SE3 = Feeder swing-out (6 wedges at PCD 190)
      SE4 = Yarn threading (operator hand path)
      SE5 = Belt replacement (30 mm motor X-travel)
      Each envelope has 6 fields: purpose, protected volume,
        entry direction, tool access, prohibited geometry,
        future-risk notes.

  (e) ANGULAR_REFERENCE_STANDARD.md R1  (NEW, 2026-05-20)
      Locks the "theta=0 is NOT front" rule.
      theta=0 = +X = motor side = Hall index = Slot #0
      theta=90 = +Y = operator front
      Feeder positions F1-F6 numbered at 0/60/120/180/240/300 deg.
      Phase 1 ACTIVE = F1 (theta=0) + F4 (theta=180).
      F2/F3/F5/F6 = retainer-ring mount bolts (NOT empty).

  (f) machine_datums.py             (Python mirror)
      Self-checking module that mirrors MACHINE_DATUMS.md.
      Imports into every macro: NO hardcoded coords anywhere.
      Asserts derived CYL_BOTTOM_WORLD_Z matches the constant.

THE SIX DOCUMENTS NOW FORM A COHERENT GOVERNANCE STACK:

4. THE BEHAVIORAL SIMULATOR (Phase 1.5)
================================================================

Conceptual evolution:

  Initial: "Phase 1.5 = animate the cylinder rotating in Blender"
  Refined: "Phase 1.5 = build the first BEHAVIORAL SIMULATOR"

Three tracks per simulation frame:
  (a) MECHANICAL STATE -- cylinder angle, needle Z, hook position
  (b) YARN STATE       -- endpoint, ownership, capture state
  (c) ERROR STATE      -- capture margin, phase, in-window flag

Deliverables built:

  D-1: Phase snapshots (nominal baseline)
       6 frames at theta = 0, 60, 120, 180, 240, 300 deg.
       Confirmed: hook peak at F1 and F4, smooth cosine bump.

  D-2: Failure mode taxonomy (8 scenarios, 4 classes)
       A. TIMING:    A1 feeder lag, A2 hook outrun, A3 belt jitter
       B. TENSION:   B1 slack loop, B2 over-tension
       C. GEOMETRIC: C1 retainer interference, C2 feeder intrusion
       D. CAPTURE:   D1 missed, D2 double-feed

  D-4 / D-4b: Parameter sweeps (21 runs, pure Python no Blender)
       A1 lag:    0, 2, 4, 6, 8, 10, 12, 15 deg
       B1 slack:  0, 2, 4, 6, 8, 12 mm
       D1 miss:   0, 2, 4, 6, 8, 12, 20 mm

  Output plots:
       capture_margin_plot.png     -- 3-panel overlay
       operating_envelope_plot.png -- worst-case vs parameter
       delta_from_nominal_plot.png -- Delta m(theta) by scenario

OPERATING ENVELOPES DERIVED FROM BEHAVIOR (acceptable at +-2 mm Z):

       A1  feeder lag           <= 10 deg     PHASE-sensitive
       B1  yarn slack           <=  2 mm      AMPLITUDE-sensitive
       D1  yarn miss / overlift =   0 mm      AMPLITUDE-sensitive (at edge!)

HIERARCHY OF FRAGILITY: D1 miss > B1 slack > A1 lag

KEY INSIGHTS THE SIMULATOR PROVED:

(a) Failure classification: phase-sensitive vs amplitude-sensitive
    Phase-asymmetric failures = timing problem (feeder lag,
       gearbox backlash, belt windup)
    Uniform offset failures = tension or geometry problem
       (take-down setup, retainer position)

(b) Take-down tension is a STITCH-FORMATION PARAMETER
    B1 slack at +-2 mm changes capture margin sign.
    Therefore take-down is coupled to capture stability,
    not downstream of it.
    -> ICD R6 elevated Interface 11 from "fabric handling"
       to "stitch formation subsystem"

(c) The cam stroke (8 mm) IS the safety budget for D1 miss
    Any yarn-presentation Z error eats directly into the
    HOOK_PEAK_Z (264) -> CYLINDER_TOP_Z (256) lift window.

  Family 5: CANONICAL POSTER V2 (single ChatGPT-generated plate)
       Adopted as project visual reference 2026-05-24.
       2.2 MB. Lives at:
         CSM_V3_ASSEMBLY/full_assembly/renders/posters/
           CSM_V3_CANONICAL_POSTER_V2.png

Key visual-design lessons:

(a) First Blender render was BAD because half the scene used
    real STLs (cassette, drive train) and half used primitive
    boxes/cylinders (motor, frame, electronics). Mismatched
    fidelity hurts more than low fidelity uniformly applied.

(b) The "doesn't look good" was caused by:
    - Wrong frame proportions (table-on-table instead of single base)
    - Mast competing with cassette for visual attention
    - Cones loose on table (not on feeder modules)
    - Electronics hidden far below drive train
    All fixed in ICD R3 architecture rewrite.

(c) ChatGPT-generated marketing-style posters CAN match
    engineering CAD honesty IF the source data is locked
    architecture (which only became true after MD R4 + ICD R6).
    Before architecture lock, AI illustration = "concept art".
    After architecture lock, AI illustration = "engineering plate".

(d) Failure visualization is more informative than nominal-
    operation visualization. The 8 failure stills + the delta
    plot expose tolerance margins; the nominal renders only
    confirm geometry.

6. CYLINDER V3.0 -> V3.1 FROM PHYSICAL TEST
================================================================

Test setup:
  - Printed WEDGE_B V2 (10-slot fine sweep 3.50..5.30 mm)
  - 12g FlyDesigns latch needles
  - Manual insertion + retention evaluation

Result:
  Slot 6 (4.50 mm depth, 2.90 mm groove)  -- tie / acceptable
  Slot 7 (4.70 mm depth, 3.10 mm groove)  -- BEST -- winner
  Slot 8 (4.90 mm depth, 3.30 mm groove)  -- loose -- past the edge

Lock (machine_datums.py + MACHINE_DATUMS R5):
  SLOT_DEPTH        = 4.70 mm  (was 3.00 in V3.0)
  SPRING_GROOVE_DEPTH = 3.10 mm  (was 1.30 in V3.0)
  Cylinder version V3.0 -> V3.1

Mechanical bonus discovered:
  V3.0 spring protruded 1.49 mm past cylinder OD --
    was eating into the 0.7 mm/side cam ring clearance.
  V3.1 spring is RECESSED 0.31 mm below OD --
    zero risk of cam ring interference.
  Better retention AND cleaner cam interaction.

This is the most important engineering result of the entire
session: the FINAL production cylinder geometry was derived
from PHYSICAL test data, not from intuition or first-principles
math. That is the correct engineering progression.

7. REPEATED PATTERNS AND LESSONS
================================================================

(a) Architecture before geometry.
    Every time we tried to build geometry before locking the
    architecture (early Blender renders, V11 BOM motor decisions),
    rework followed. Every time we locked architecture first and
    let geometry follow (V3.1 cylinder, V12 BOM, Phase 1.5 sim),
    work compounded cleanly.

(b) BOM is the canonical reality.
    Architectural decisions made WITHOUT reading the BOM consistently
    diverged from physical reality. The discovery moment
    ("read the BOM!") was 2026-05-22; everything after that aligned.

(c) Behavior beats appearance.
    The 6-view canonical poster only earned its place after
    Phase 1.5 simulation results gave it real numerical grounding.
    Before that, posters were aesthetic interpretation.

(d) Documentation discipline scales.
    With 5 governance docs (MCS / MD / ICD / SE / ARS), changes
    can be made confidently because invariants are protected
    and revision history is auditable.

(e) Test-driven geometry.
    WEDGE_B physical test gave the cylinder its final lock.
    No amount of CAD precision substitutes for "push a needle
    into a printed slot and see what holds."

(f) Honesty about scope.
    Every "we'll add this in Phase 2/3" was logged explicitly.
    Includes: dual-roller take-down, ribber, vacuum assist,
    closed-loop tension, automatic heel/toe, multi-feed color
    changes, FeederModule V1.2 ceramic pigtail.

(g) Service envelopes are first-class objects.
    Most DIY machines fail not at assembly but at first service.
    SE1-SE5 prevent that by making maintenance access part of
    the geometry from day 1, not an afterthought.
