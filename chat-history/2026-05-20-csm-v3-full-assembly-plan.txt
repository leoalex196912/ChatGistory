================================================================
CONTEXT
================================================================

The 2026-05-19 Blender hero render used real STLs for the locked
mechanical parts (cylinder, cam ring, sinker, cassette base, retainer,
drive hub, motor mount, bearing housings) BUT used Blender primitives
(boxes, cylinders, cones) for everything else (motor, pulleys, belt,
shaft, frame, electronics, yarn cones).

The user (correctly) pointed out that the render "doesn't look good"
because half the scene is engineering-grade STLs and half is grade-school
primitives. The right approach is to build EVERY part of the assembly
the same way we built the mechanical components: as a parametric FreeCAD
macro that exports an STL with dimensions pulled from MACHINE_DATUMS.md.

================================================================
PROXIMA AUDIT SUMMARY (security check before install)
================================================================

Repo:  https://github.com/Zen4-bit/Proxima
Stage: v4.1.0
What:  Local Electron app that drives ChatGPT/Claude/Gemini/Perplexity
       web sessions via injected JS engines, exposes them as MCP +
       REST + WebSocket on localhost:3210.

Audit verdict: SAFE TO INSTALL.

Checks:
  - Dependencies clean (only @modelcontextprotocol/sdk, ws, zod)
  - No telemetry/analytics packages
  - No autoUpdater / electron-updater
  - No child_process / exec() / spawn() shell calls
  - No eval() / Function() / vm.runInThisContext
  - Engine scripts (claude-engine.js, chatgpt-engine.js, etc.) only
    talk to their own provider domains using session cookies
  - Preload bridge is standard contextBridge pattern, no IPC
    suspiciousness
  - All fetch() calls in engines are relative URLs that resolve to
    the provider domain the engine is injected into

Risks (real but manageable):
  - TOS gray area (OpenAI prohibits automated access to ChatGPT).
    Low-volume design-review usage is unlikely to trip flags.
  - Session fragility: 404/410/auth-expired triggers handled in code
    but each provider API change requires maintainer to ship a fix.
  - Single-maintainer project (Zen4-bit). Forkable if abandoned.
  - Non-commercial license. Fine for prototype; matters if CSM V3
    ships as product.
